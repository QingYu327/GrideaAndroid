部署配置

Gridea Android 提供五条直连部署通道：GitHub Pages、Gitee Pages、Netlify、Vercel、SFTP。部署在后台 Service 中执行，支持中断、进度通知与失败重试，完成后自动写入部署历史。

GitHub Pages

最常用的部署方式。你的博客会托管在 yourname.github.io 仓库下。

  1. 在 GitHub 创建仓库，命名为 <用户名>.github.io（例如 limengrid.github.io）。
  2. 前往 GitHub Settings → Developer settings → Personal access tokens，生成一个 Classic Token，至少勾选 repo 权限。
  3. 在 App「设置 → 部署 → GitHub Pages」中填写：仓库拥有者、仓库名、分支（默认 master 或 main）、Token。
  4. 点击「部署」。App 通过 Contents API 逐文件 PUT，文件间间隔 1 秒以防触发限流。

Token 安全：Token 保存在本地 DataStore 中，不上传任何服务器。反馈日志打包时会自动脱敏，仅保留前缀。

Gitee Pages

面向国内用户的代码托管平台，访问速度更稳定。配置方式与 GitHub 类似：

  1. 在 Gitee 创建同名仓库 <用户名>.github.io 或自定义仓库名。
  2. 在 Gitee「设置 → 私人令牌」生成令牌，需 projects 与 pull_requests 等权限。
  3. 在 App 中填写 Gitee 凭证并部署。采用 PUT + DELETE 策略同步删除已移除的文件。

Gitee 部署失败时提供 404 增强诊断，会在日志中标注缺失资源路径，便于排查主题资源引用问题。

Netlify

Netlify 通过 SHA1 增量上传，只推送缺失或变更的文件，适合文章量大时加速部署。

  1. 在 Netlify 创建站点并记录站点 ID。
  2. 在「User Settings → Applications」生成 Personal Access Token（Bearer Token）。
  3. 在 App「设置 → 部署 → Netlify」中填写站点 ID 与 Bearer Token。
  4. 部署时 App 计算每个文件 SHA1，仅上传远端不存在的文件。

Vercel

Vercel 采用 SHA 去重策略，可作为 Gitee Pages 的替代方案。配置：

  1. 在 Vercel Account → Tokens 生成 Token。
  2. 创建项目并记录 Project ID 与所属 Team ID（个人账户可留空）。
  3. 在 App 中填写上述信息后部署。App 会对文件做 SHA 去重，避免重复上传。

SFTP

SFTP 适合自建服务器场景，支持密码与私钥两种认证方式。底层使用 JSch（mwiede fork，修复了旧版安全漏洞）。

  1. 填写服务器地址、端口（默认 22）、用户名。
  2. 选择认证方式：密码，或粘贴私钥内容。
  3. 填写远程站点根目录，例如 /var/www/blog。
  4. SFTP 采用全量替换策略，部署时会清空目标目录后重新上传全部文件。

注意：SFTP 全量替换会删除目标目录下的所有内容。请确保填写的根目录只用于博客，避免误删其他站点文件。

部署过程

无论选择哪条通道，部署流程都在后台 Service 中执行：

  • 构建：用 Pebble 渲染所有页面，生成静态 HTML / CSS / JS / 图片。
  • 上传：按通道策略上传文件，进度以通知形式展示。
  • 历史：部署完成后自动写入部署历史，记录时间、通道、文件数、耗时。
  • 中断与重试：部署可随时中断；失败时支持重试，无需重新构建。

部署历史

在「设置 → 部署历史」可查看所有部署记录。每条记录包含部署时间、通道、成功 / 失败状态与日志摘要。失败的部署可一键重试。
