Gridea Android 文档

欢迎使用 Gridea Android。这是一款专为 Android 设计的静态博客写作客户端——无需电脑、无需服务器，一部手机即可完成「写作 → 预览 → 部署」的全流程。本文档将带你了解应用的安装、写作、主题、部署与各项设置，帮助你把静态博客装进口袋。

快速开始

简介

Gridea Android 是开源静态博客工具 Gridea 的 Android 原生实现。它在原有理念的基础上，针对移动平台从底层重新设计：采用 100% Jetpack Compose 构建 UI，内置 Markwon Markdown 编辑器、Pebble 模板引擎，以及直连 GitHub Pages、Gitee、SFTP、Netlify、Vercel 五大平台的部署能力。

所有数据存储在应用沙箱内，不上传任何服务器。你拥有对自己内容的完全控制权——从写作到发布，整条链路都在你的手机上完成。

  • 纯本地：文章、配置、主题全部存储在应用沙箱，离线可用。
  • 无后端：部署直连你自己的代码托管平台，不经过任何中间服务器。
  • 开箱即用：图形化界面，无需命令行，无需配置 Node.js 或 Git 环境。

安装指南

Gridea Android 通过 GitHub Releases 分发 APK 安装包，暂未上架 Google Play。请按以下步骤完成安装：

  1. 前往 GitHub Releases 页面，下载最新版本的 app-release.apk。
  2. 在手机上点击下载好的 APK，系统会提示「为了你的安全……」——这是因为应用未经过 Play 商店签名，选择「仍然安装」。
  3. 若系统要求开启「允许安装未知来源应用」，请在系统设置中为浏览器或文件管理器开启该权限，再返回重试。
  4. 安装完成后打开应用，即可看到欢迎引导。

系统要求：Android 7.0（API 24）及以上。应用支持亮色 / 暗色 / 跟随系统三种主题模式，Android 12+ 可启用动态取色。

首次配置

首次打开 App 后，会进入引导流程，带你完成站点的基础设置。这些信息会写入你的博客站点，并保存在本地 DataStore 中。

引导流程

  1. 欢迎页介绍应用的核心能力与隐私承诺。
  2. 填写站点基础信息（站点名称、描述、作者）。
  3. 从内置主题中选择一款作为初始主题。
  4. 完成引导，进入主界面开始写作。

配置站点信息

  • 站点名称：显示在浏览器标签和博客首页，例如「我的博客」。
  • 站点描述：一句话介绍你的站点，用于 SEO 与 RSS。
  • 作者：展示在文章作者栏与友链页。

选择主题

应用内置 7 套主题，可在「主题」页面随时切换。每套主题都为手机端做了响应式适配。建议先用默认主题跑通流程，再慢慢挑选喜欢的风格。详见 主题系统。

提示：站点 URL（部署地址）可在正式部署前再填写。如果暂时没有地址，先留空即可，部署前记得回来改成真实地址，否则文章永久链接会指向错误位置。

写作

Markdown 编辑器

Gridea Android 内置基于 Markwon 引擎的 Markdown 编辑器，支持完整的 Markdown 语法以及丰富的扩展能力，让你在手机上也能拥有接近桌面端的写作体验。

  • 基础语法：标题、粗体、斜体、删除线、引用、链接、图片、有序 / 无序列表、表格、分割线。
  • 代码高亮：支持常见编程语言的语法高亮，可编写行内代码与围栏代码块。
  • 任务列表：使用 - [ ] / - [x] 创建可勾选任务项。
  • 上下标：支持 ~下标~ 与 ^上标^ 语法，便于书写数学与化学公式。
  • 高亮标记：使用 ==高亮== 标记重点内容。
  • 工具栏快捷操作：顶部工具栏提供加粗、斜体、列表、链接、图片等常用操作的快捷按钮，避免在手机键盘上反复输入符号。

编辑器还支持封面图设置、标签管理、草稿状态切换。文件名会根据标题自动生成 URL 友好的 slug。

自动保存与版本历史

为了让你专注于内容、无惧修改，编辑器提供了完善的自动保存与版本历史机制。

  • 2 秒自动保存：每次停笔 2 秒后，编辑器会自动将当前内容写入本地数据库。你也可以随时手动点击保存按钮。
  • 每 2 分钟生成版本快照：在写作过程中，应用每隔 2 分钟为文章生成一个版本快照，记录当时的完整内容。
  • 回滚到任意历史版本：在文章的「版本历史」面板中，你可以浏览所有快照，预览任意历史版本的内容，并一键回滚到该版本。

提示：版本快照存储在本地，不会随部署上传。如果你更换设备，记得通过「数据备份」导出文章数据。

查找替换

编辑器内置 IDE 风格的查找替换面板，便于在长文中快速定位与批量修改内容。

  • 查找与替换：支持输入关键词查找，并替换为指定文本，可选择「替换当前」或「全部替换」。
  • 匹配项高亮：所有匹配项会在编辑区实时高亮，当前定位项以不同颜色突出显示。
  • 上一个 / 下一个：在多个匹配项之间快速跳转，匹配数量实时统计。

写作统计

应用会记录你的写作行为，并用可视化的方式呈现，帮助你养成持续创作的习惯。

  • 写作时长记录：自动统计你在编辑器中的累计写作时长。
  • 字数目标进度条：可设置每日字数目标，进度条实时显示当日完成情况。
  • 文章热力图：以热力图形式展示过去一段时间内的写作活跃度，颜色深浅对应当天字数。

主题

主题系统

Gridea Android 使用 Pebble 模板引擎渲染站点，通过 theme.json 在应用与主题之间建立配置通信契约。主题系统具备以下特性：

  • 内置 7 款主题：涵盖杂志、复古、终端、马卡龙、水墨、侧边栏等多种风格，开箱即用。
  • .zip 主题包导入：将第三方主题打包为 .zip，在「主题」页面导入即可使用。
  • 即时预览：修改主题配置后，预览页面会立即重新渲染，无需重新部署即可看到效果。
  • 三端响应式：所有主题均适配手机、平板、电脑三种屏幕尺寸。

theme.json 配置

theme.json 是主题与应用之间的通信契约。它声明主题支持哪些可配置项，应用据此在设置界面生成对应的配置控件，并将用户填写的值回传给模板渲染。

customConfig 数组

主题的所有可配置项都放在 customConfig 数组中，每一项定义一个配置控件。

5 种控件类型

  • text：单行文本输入，适用于标题、副标题、自定义文案等。
  • switch：开关，适用于布尔型选项，如是否显示某个模块。
  • slider：滑块，适用于数值范围调节，如列数、字号缩放。
  • code：多行代码输入，适用于自定义 CSS / JS 注入。
  • multiselect：多选，适用于从预设选项中选择多个值，如启用的社交图标。

统计字段

主题可声明以下统计代码字段，用户填写对应 ID 后即可接入第三方统计：

  • ga：Google Analytics。
  • baidu：百度统计。
  • tencent：腾讯统计。
  • view：自定义访问统计脚本。

主题开发指南

如果你想开发自己的主题，需要遵循以下规范。

主题包结构

一个完整的主题包（.zip）应包含以下文件结构：

my-theme/
├── theme.json              # 主题配置契约
├── config.json             # 主题默认配置
├── templates/              # Pebble 模板
│   ├── index.html          # 首页
│   ├── post.html           # 文章页
│   ├── archive.html        # 归档页
│   ├── tag.html            # 标签页
│   └── partials/           # 公共片段
│       ├── header.html
│       └── footer.html
└── assets/                 # 静态资源
    ├── css/
    ├── js/
    └── images/

Pebble 模板语法要点

  • 变量输出：{{ post.title }} 输出变量值。
  • 继承与块：使用 {% extends "partials/header.html" %} 与 {% block content %}...{% endblock %} 实现模板复用。
  • 循环：{% for post in posts %}...{% endfor %} 遍历文章列表。
  • 条件判断：{% if post.cover %}...{% endif %} 控制内容显隐。
  • 过滤器：使用 {{ post.date | date("YYYY-MM-DD") }} 格式化日期等。
  • 配置引用：通过 {{ customConfig.xxx }} 读取用户在应用中填写的主题配置值。

响应式要求

  • 必须适配手机、平板、电脑三端屏幕，建议使用流式布局与媒体查询。
  • 图片应使用 max-width: 100% 避免溢出。
  • 交互元素（链接、按钮）的点击区域应足够大，便于手机触控。

提示：开发完成后，将主题目录打包为 .zip（直接压缩目录内容，不要嵌套一层父目录），然后在应用「主题」页面导入即可测试。

部署

Gridea Android 提供五条直连部署通道：GitHub Pages、Gitee + EdgeOne、SFTP、Netlify、Vercel。部署在后台 Service 中执行，支持中断、进度通知、失败重试，完成后自动写入部署历史。各通道的配置相互隔离，互不影响。

GitHub Pages

最常用的部署方式。你的博客会托管在 yourname.github.io 仓库下。

  1. 创建仓库：在 GitHub 创建仓库，命名为 <用户名>.github.io（例如 limengrid.github.io）。
  2. 创建 Personal Access Token：前往 GitHub Settings → Developer settings → Personal access tokens，生成一个 Classic Token，至少勾选 repo 权限。
  3. 填写配置：在「设置 → 部署 → GitHub Pages」中填写：用户名（仓库拥有者）、仓库名、分支（默认 master 或 main）、Token。
  4. 部署：点击「部署」，应用通过 Contents API 逐文件 PUT 上传，文件间间隔 1 秒以防触发限流。完成后访问 https://yourname.github.io 即可看到博客。

Token 安全：Token 保存在本地 DataStore 中，不上传任何服务器。反馈日志打包时会自动脱敏，仅保留前缀。

GitHub OAuth 登录

除了使用 Personal Access Token，应用还支持通过 GitHub OAuth Device Flow（设备流） 授权登录，免去手动创建和管理 Token 的繁琐流程。Device Flow 是 OAuth 2.0 为移动端和嵌入式设备设计的授权流程，无需 Client Secret，安全性更高。

Device Flow 工作原理

与传统 OAuth 回调流不同，Device Flow 不需要应用嵌入浏览器或注册回调 URL。流程如下：

  1. 应用向 GitHub 请求一个设备码（Device Code），同时获得一个用户码（User Code）和验证网址。
  2. 应用显示用户码和验证网址（https://github.com/login/device）。
  3. 你在任意设备（手机浏览器、电脑浏览器均可）打开该网址，登录 GitHub 并输入用户码。
  4. 应用在后台按固定间隔轮询 GitHub 的 Token 接口，一旦你完成授权，应用自动获取 Access Token。
  5. Token 写入本地 DataStore，后续部署直接复用，无需再手动填写。

安全说明：整个过程中应用无法获取你的 GitHub 密码，Client Secret 也不需要（Device Flow 不使用）。Token 仅存储在本地，不上传任何服务器。授权范围仅限 repo（仓库读写）与 user（读取用户资料），不会请求超出部署所需的权限。

配置步骤

  1. 创建 OAuth App：前往 GitHub Settings → Developer settings → OAuth Apps → New OAuth App。
  2. 填写应用信息：
    • Application name：自定义，如 Gridea Android。
    • Homepage URL：填你的博客地址或任意有效 URL。
    • Authorization callback URL：填任意有效 URL（如 http://localhost:8080），Device Flow 不实际使用回调。
  3. 启用 Device Flow：创建完成后，进入 OAuth App 详情页，找到 「Enable Device Flow」 选项并勾选。这一步必须开启，否则登录会失败。
  4. 记录 Client ID：在 OAuth App 详情页复制 Client ID（20 位十六进制字符串）。不需要生成 Client Secret。
  5. 应用内填写：打开 App →「设置 → 账户」，在 OAuth App 配置卡片中填入 Client ID。
  6. 开始登录：点击「使用 GitHub 登录」按钮，应用会显示一个用户码（如 WDJB-MJHT）和验证网址。
  7. 浏览器授权：点击验证网址（github.com/login/device）用系统浏览器打开，登录 GitHub 并输入用户码，点击 Authorize 授权。
  8. 完成：应用轮询到 Token 后自动拉取你的 GitHub 账户信息（头像、用户名、仓库数等），界面切换到「已登录」状态，提示「登录成功」。

提示：登录成功后，在部署配置页（GitHub Pages）的 Token 输入框下方，会出现「使用已登录账户的 Token」按钮，点击即可一键复用 OAuth Token，无需再手动创建 Personal Access Token。

Gitee + EdgeOne 静态托管

面向国内用户的部署方案。注意：Gitee Pages 服务已关闭，不再提供静态网站托管。当前方案为：应用通过 Gitee API 将静态文件推送到 Gitee 仓库，再通过腾讯云 EdgeOne 的静态托管服务接入该仓库完成站点托管。Gitee 仓库仅作为文件存储，真正的站点托管由 EdgeOne 完成。Gitee 凭证与 GitHub 完全隔离，可同时部署到两个平台。

第一步：Gitee 仓库与令牌配置

  1. 创建仓库：在 Gitee 创建仓库，命名自定义（如 my-blog）。仓库可以是公开或私有，EdgeOne 均可接入。
  2. 创建私人令牌：进入 Gitee「设置 → 私人令牌」，生成新令牌，勾选 projects 权限。令牌仅显示一次，请妥善保存。
  3. 应用内配置：在「设置 → 部署 → Gitee」中填写 Gitee 用户名、仓库名、分支（默认 master）与私人令牌。
  4. 部署：点击「部署」，应用通过 Gitee Contents API 逐文件上传（Base64 编码），采用 PUT + DELETE 策略同步删除已移除的文件。每次上传间隔 1 秒以防触发限流。部署完成后，文件即存储在 Gitee 仓库中。

说明：应用仅负责将文件推送到 Gitee 仓库，不涉及 Gitee Pages 服务。仓库中的文件需要通过下方 EdgeOne 静态托管才能作为网站访问。

第二步：配置腾讯云 EdgeOne 静态托管

EdgeOne 提供 Pages 类型的静态站点托管服务，可以接入 Git 仓库自动部署。每次应用向 Gitee 仓库推送新内容后，EdgeOne 会自动检测到仓库更新并触发重新部署。

  1. 注册腾讯云账号：前往 EdgeOne Pages，注册并完成实名认证。
  2. 创建 EdgeOne 站点：在 EdgeOne 控制台点击「新建站点」，输入你的自定义域名（如 blog.example.com），选择「接入 EdgeOne」。
  3. 接入方式：选择「CNAME 接入」。EdgeOne 会生成一个 CNAME 地址（如 xxx.cdn.dnsv1.com），将其记录下来。
  4. 配置 DNS 解析：在你的域名 DNS 管理处，添加一条 CNAME 记录：
    • 主机记录：blog（或你使用的子域名前缀）
    • 记录类型：CNAME
    • 记录值：EdgeOne 提供的 CNAME 地址
  5. 创建静态托管：在 EdgeOne 控制台找到「站点加速 → 静态托管」或「Pages」服务，创建新的托管项目。
  6. 接入 Gitee 仓库：在托管项目中，选择「Git 仓库接入」，授权并选择你的 Gitee 仓库与分支。EdgeOne 会自动拉取仓库内容进行托管。
  7. 配置构建规则（可选）：如果你的静态文件直接在仓库根目录，无需构建命令，指定输出目录为根目录（/）即可。
  8. 申请 SSL 证书：在「站点加速 → 域名管理 → HTTPS 配置」中，选择「免费证书」，EdgeOne 会自动申请并部署 Let's Encrypt 证书，开启强制 HTTPS 跳转。
  9. 验证访问：DNS 生效后（通常 5-10 分钟），通过自定义域名访问博客，确认页面正常加载且证书有效。

第三步：在应用中更新站点域名

托管配置完成后，回到应用「设置 → 站点信息 → 域名」，将地址更新为 EdgeOne 托管后的自定义域名（如 https://blog.example.com），确保文章永久链接与 RSS 指向正确地址。

提示：每次在应用中重新部署后，Gitee 仓库内容会更新，EdgeOne 会自动检测到仓库变更并重新部署。如需立即刷新缓存，可在 EdgeOne 控制台「缓存配置 → 刷新预热」中手动刷新 URL。

SFTP

SFTP 适合自建服务器场景，支持密码认证。底层使用 JSch（mwiede fork，修复了旧版安全漏洞）。

  • 服务器要求：需提供可用的 SFTP 服务（默认端口 22），并拥有目标目录的读写权限。

配置项

  • 服务器地址：如 ftp.example.com 或 IP。
  • 端口：默认 22。
  • SFTP 用户名：登录用户名。
  • 密码：登录密码。
  • 远程路径：站点根目录，例如 /var/www/blog。

注意：SFTP 配置与 GitHub 完全隔离，切换部署平台不会互相干扰。SFTP 采用全量替换策略，部署时会清空目标目录后重新上传全部文件，请确保填写的根目录只用于博客，避免误删其他站点文件。

Netlify

Netlify 通过 SHA1 增量上传，只推送缺失或变更的文件，适合文章量大时加速部署。

  1. 在 Netlify 创建站点并记录 Site ID。
  2. 在「User Settings → Applications」生成 Personal Access Token。
  3. 在「设置 → 部署 → Netlify」中填写 Site ID 与 Access Token。
  4. 部署时应用计算每个文件 SHA1，仅上传远端不存在的文件，实现增量部署。

Vercel

Vercel 采用 SHA 去重策略，上传时自动跳过未变更文件，适合频繁部署场景。

  1. 在 Vercel Account → Tokens 生成 Access Token。
  2. 创建项目并记录 Project ID（所属 Team ID，个人账户可留空）。
  3. 在应用中填写上述信息后部署。应用会对文件做 SHA 去重，避免重复上传。

设置

站点配置

在「设置 → 站点信息」中配置站点的全局属性，这些信息会影响博客的展示与 SEO。

  • 站点名称、描述、作者：展示在首页、浏览器标签与 RSS 中。
  • 域名：博客最终部署的访问地址，如 https://yourname.github.io。务必填写准确，它会影响文章永久链接与 RSS 生成。
  • CNAME：若使用自定义域名，可在此填写 CNAME 记录，部署时会自动写入仓库根目录。
  • 文章分页：设置首页每页显示的文章数量。
  • URL 格式：选择文章永久链接的格式（如默认、日期型、可读型）。
  • 日期格式：自定义文章日期的展示格式。

评论系统

应用支持接入主流的评论系统，让你在静态博客上也能拥有互动能力。支持以下六种：

  • Gitalk：基于 GitHub Issue 的评论系统。
  • Giscus：基于 GitHub Discussions 的评论系统。
  • Disqus：国际通用的评论系统。
  • Valine：基于 LeanCloud 的无后端评论系统。
  • Twikoo：私有部署的评论系统。
  • Waline：具备完整后端的评论系统。

配置方法

  1. 在对应评论系统的官方平台完成注册与初始化，获取所需的 ID、密钥或仓库信息。
  2. 在「设置 → 评论」中选择使用的评论系统。
  3. 按页面提示填写对应字段（如 GitHub 仓库、Client ID、LeanCloud AppID 等）。
  4. 保存后预览站点，评论组件会自动加载到文章页底部。

提示：部分评论系统（如 Disqus）在国内访问可能不稳定，建议国内用户优先考虑 Twikoo、Waline 或 Giscus。

外观与主题

在「设置 → 外观」中个性化你的应用与站点外观。

  • 主题模式：亮色 / 暗色 / 跟随系统，三种模式自由切换。
  • 动态取色：Android 12+ 可启用 Material You 动态取色，应用主色随壁纸自动变化。
  • 自定义强调色：手动指定应用的主题强调色。
  • 字体大小缩放：调节应用内字体大小，适配不同视力需求。
  • 语言：中文 / 英文 / 跟随系统，三种语言选项。

数据备份

为防止数据丢失，应用提供完善的备份与恢复机制。

  • 自动备份：应用会定期自动备份文章与配置数据到本地。
  • 手动备份与恢复：在「设置 → 数据备份」中可手动导出完整数据备份包，也可从备份包恢复数据到应用，便于更换设备或归档留存。

建议：定期将备份包复制到云盘或电脑，避免因设备丢失或卸载应用导致数据丢失。

其他

桌面小部件

应用提供两款桌面小部件，让你无需打开 App 即可快速操作。

  • 1×1 新建文章小部件：点击即可跳转到编辑器新建一篇文章，捕捉转瞬即逝的灵感。
  • 4×1 写作统计小部件：在桌面展示当日字数目标进度与累计写作时长，时刻激励自己持续创作。

添加方法

长按桌面空白处 → 选择「小部件」→ 找到「Gridea Android」→ 将对应小部件拖到桌面即可。

调试模式

调试模式面向进阶用户与主题开发者，默认隐藏，需手动解锁。

  • 解锁方式：进入「关于」页面，连续点击版本号 5 次即可解锁调试模式。
  • WebView 远程调试：开启后，可用 Chrome DevTools 远程审查预览页面的 DOM、网络与控制台，便于调试主题。
  • 详细日志：开启后会记录更详细的运行日志，便于排查部署失败等问题。

提示：调试日志可能包含敏感信息（如 Token 前缀）。分享日志前，应用会自动脱敏处理，但仍建议你检查一遍再分享。

常见问题

打开应用后白屏怎么办？

白屏通常与 WebView 加载失败或主题渲染异常有关。可尝试：清除应用缓存后重启；切换为默认主题后重新预览；若仍无效，开启「调试模式 → WebView 远程调试」用 Chrome DevTools 查看控制台报错定位问题。

GitHub Pages 部署后页面空白？

常见原因是站点 URL 配置错误，导致资源路径指向错误位置。请检查「设置 → 站点信息 → 域名」是否与实际访问地址完全一致（含 https:// 前缀，末尾无多余斜杠）。另外确认仓库已开启 Pages 服务且分支选择正确。

主题预览不生效？

修改主题配置后预览未更新，通常是预览缓存未刷新。请尝试在预览页面下拉刷新或重新进入预览。若导入的是自定义主题，检查 theme.json 格式是否正确、模板文件是否齐全。

SFTP 部署失败？

请依次排查：服务器地址与端口是否正确；用户名密码是否准确；远程路径是否存在且具备读写权限；服务器 SSH 服务是否正常运行。SFTP 采用全量替换策略，若根目录权限不足会导致清空失败。可在「调试模式 → 详细日志」中查看具体错误信息。

如何在不同设备间同步文章数据？

应用目前不提供云同步功能，所有数据存储在本地。如需在设备间迁移，请在旧设备的「设置 → 数据备份」中导出完整备份包，将备份文件传输到新设备后，在同一页面选择「恢复数据」即可。备份包含所有文章、配置、主题设置与版本历史。建议将备份包同时保存到云盘，以防设备丢失。
