常见问题

日志管理

Gridea Android 内置 AppLogger 分级日志系统，覆盖渲染、预览、主题、WebView 全流程。出问题时无需 logcat，在应用内即可定位原因，并一键打包脱敏后通过反馈通道提交。

日志分级

AppLogger 采用五级日志，便于过滤与定位：

级别用途示例
INFO常规流程信息「开始构建」「部署完成」
WARN非致命异常「主题缺少 friends.peb，跳过友链页」
ERROR错误「部署失败：401 Unauthorized」
ACTION用户操作记录「切换主题 → ink」「保存文章」
DEBUG调试细节「渲染耗时 328ms」「上传 23 个文件」

覆盖范围

日志覆盖以下四个关键环节：

  • 渲染日志：Pebble 模板渲染过程，记录渲染耗时、生成的页面数、模板错误。
  • 预览日志：WebView 加载事件，含 JS Bridge 回传的点击、console、资源加载失败、404。
  • 主题日志：主题切换、配置变更、资源注入情况。
  • WebView 日志：页面控制台输出、加载进度、外链拦截。

查看日志

在「设置 → 日志」可查看实时日志面板：

  • 按级别过滤（INFO / WARN / ERROR / ACTION / DEBUG）。
  • 按关键词搜索。
  • 按时间范围筛选。
  • 清空当前日志。

日志默认按时间倒序排列，最新事件置顶。ERROR 级别会以醒目颜色标注。

一键反馈

遇到问题想提交给开发者时，使用「设置 → 问题反馈」：

  1. App 自动收集最近一段时间的日志（含渲染、预览、主题、WebView）。
  2. 打包前自动脱敏：Token、私钥、密码等敏感字段仅保留前缀，其余以 *** 替代。
  3. 生成一个 .zip 反馈包。
  4. 通过系统分享面板发送给开发者（邮件、IM、GitHub Issue 附件等）。

脱敏保证：反馈包不会包含你的完整 Token 或私钥。例如 ghp_xxxxABCD1234 会被处理为 ghp_x***。

常见问题排查

部署失败

在日志面板过滤 ERROR，常见的部署错误：

  • 401 Unauthorized：Token 错误或过期，重新生成。
  • 404 Not Found：仓库不存在或仓库名拼写错误。
  • 403 Rate Limit：GitHub 限流，稍后重试（App 已做 1 秒间隔，但仍可能触发）。

主题资源 404

预览日志中的「资源加载失败」会记录具体路径。常见原因是 theme.json 声明了资源但 assets 目录缺失对应文件，或模板中引用路径错误。

页面空白

若预览页空白，多为 base.peb 语法错误导致渲染失败。查看渲染日志的 ERROR 条目，会标注出错模板与行号。
