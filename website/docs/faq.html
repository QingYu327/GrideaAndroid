常见问题

常见问题

这里收录了用户最常提出的问题。如果你的问题不在其中，欢迎在 GitHub Issues 提出，或通过应用内「问题反馈」打包日志反馈。

安装与运行

Q：为什么提示「未知来源应用」无法安装？

Gridea Android 未上架 Google Play，通过 APK 直接安装会触发系统的安全提示。在系统设置中为文件管理器或浏览器开启「允许安装未知来源应用」权限后重试即可。应用本身是开源的，源码可在 GitHub 审查。

Q：支持哪些 Android 版本？

最低支持 Android 7.0（API 24），目标版本 Android 14（API 34）。建议使用 Android 9 及以上以获得最佳体验（动态取色等特性需要较新系统）。

Q：有 iOS 版本吗？

没有。Gridea Android 是基于 Kotlin + Jetpack Compose 的 Android 原生应用，目前没有 iOS 计划。原版 Gridea 是跨平台桌面端（Windows / Mac / Linux），可按需选择。

部署相关

Q：GitHub 部署失败提示 401 怎么办？

这是 Token 无效或权限不足。请确认：① Token 未过期；② 创建时勾选了 repo 权限；③ 仓库存在且你有写入权限。可在 GitHub Token 管理页重新生成。

Q：部署后访问博客是 404？

常见原因：① 仓库名不是 <用户名>.github.io 格式，需要到仓库 Settings → Pages 手动开启；② 站点 URL 配置错误；③ GitHub Pages 还在构建中（首次部署可能需要 1-2 分钟生效）。

Q：部署很慢怎么办？

GitHub Pages 采用逐文件 PUT 且间隔 1 秒防限流，文件多时较慢。可考虑：① 使用 Netlify 或 Vercel（SHA 增量更快）；② 精简文章图片体积；③ 国内用户可用 Gitee Pages。

Q：可以同时部署到多个平台吗？

每次部署只能选择一条通道，但你可以保存多套部署配置，切换后分别部署。例如平时用 GitHub Pages，重要文章再手动部署一份到 Vercel 做镜像。

主题相关

Q：切换主题后预览没变化？

预览会立即重新渲染。若没变化，检查：① 是否真的切换成功（主题卡片高亮）；② 查看渲染日志是否有 ERROR；③ 主题包是否完整（缺 base.peb 会渲染失败）。

Q：手机上访问博客排版错乱？

所有内置主题都做了响应式适配。如果是自定义主题，请确保你的 CSS 包含 @media (max-width: 768px) 的移动端样式——这是主题审核的强制要求。

Q：能把原版 Gridea 的 EJS 主题直接用吗？

不能直接用。Gridea Android 使用 Pebble 模板引擎替代 EJS，语法不同。需要把 EJS 的 <%= %> 改为 Pebble 的 {{ }}，<% %> 改为 {% %}。变量名基本兼容。

数据与隐私

Q：我的文章会上传到服务器吗？

不会。所有文章、配置、主题数据都存储在应用本地沙箱内。只有当你主动点「部署」时，构建产物才会推送到你配置的代码托管平台。应用不连接任何 Gridea 官方服务器。

Q：卸载应用数据会丢吗？

会。卸载会清除应用沙箱内的全部数据，包括自动备份。请养成定期「导出备份」的习惯，把备份包存到云盘或下载目录。详见 备份与恢复。

Q：Token 安全吗？

Token 保存在本地 DataStore 中，不上传任何服务器，其他应用无法访问。提交反馈日志时会自动脱敏（仅保留前缀）。但仍建议为博客部署使用独立的最小权限 Token。

更新与反馈

Q：怎么检查更新？

「设置 → 检查更新」会自动查询 GitHub 最新 Release 并提示下载安装。你也可以直接关注 Release 页面。

Q：遇到 Bug 怎么反馈？

推荐使用应用内「设置 → 问题反馈」，它会自动打包脱敏日志，通过系统分享发送。你也可以直接在 GitHub Issues 提交，附上日志面板的 ERROR 截图。

Q：可以参与开发吗？

欢迎！项目遵循 GPL-3.0 开源，PR 详见仓库的贡献指南。主题开发参考 主题开发 章节。
