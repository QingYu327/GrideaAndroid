常见问题

站点预览

写完文章、切换主题、修改配置后，无需部署即可在「预览」标签页即时看到效果。预览使用系统 WebView 加载本地构建产物，与浏览器表现一致。

预览原理

切换到预览页时，App 会用 Pebble 渲染当前所有已发布文章与站点配置，生成静态文件写入本地沙箱，再用系统 WebView 加载 file:// 协议的 index.html。整个过程在本地完成，不依赖网络。

  • 切换主题、修改主题配置后，预览立即重新渲染。
  • 新建 / 编辑文章后，预览同步刷新。
  • 预览只加载本地 file:// 产物，不加载任何外部 CDN（评论系统 CDN 在预览模式下自动跳过）。

浏览器级导航

预览页提供返回上一页 / 前进下一页按钮，遵循浏览器历史栈语义：

  • 返回：优先回退 WebView 历史；若已到栈底，则交由系统手势返回上一界面。
  • 前进：在历史栈中前进。
  • 按钮的启用 / 禁用状态实时同步 canGoBack / canGoForward。

外链处理

预览页内的 http / https 链接不会在应用内加载，而是自动调起系统浏览器打开。这避免了在 WebView 中跳转到第三方站点导致导航混乱，也更安全。

JS Bridge

App 在预览 WebView 中注入了 GrideaPreview 桥接对象，把页面行为回传到 AppLogger，方便排查主题问题：

事件说明
点击页面内点击事件回传，定位交互问题
console 日志页面 console.log/error 转发到 AppLogger
资源加载失败JS / CSS / 图片加载失败时记录路径
404页面未找到时记录请求路径

这意味着开发主题时无需连接 logcat，直接在 App 内的日志面板就能看到主题的报错信息。

远程调试

需要更深入的调试时，可开启 Chrome DevTools 远程审查：

  1. 进入「设置 → 调试模式」，开启「WebView 远程调试」。
  2. 用 USB 连接电脑，或在同一网络下使用无线调试。
  3. 在电脑 Chrome 浏览器访问 chrome://inspect。
  4. 在设备列表中找到 Gridea 的 WebView，点击「inspect」即可打开 DevTools。

调试完成后建议关闭远程调试开关，避免在公共网络下暴露调试端口。

预览技巧

  • 预览是部署的「彩排」——预览没问题，部署基本就没问题。
  • 主题资源 404 是最常见问题，结合 JS Bridge 的资源加载失败日志快速定位。
  • 预览模式下评论系统的外部 CDN 会自动跳过，所以预览看不到评论属正常现象。
